# Notifications — Design Spec

**Date:** 2026-09-05
**Status:** Awaiting review
**Scope:** Backend (NestJS) + mobile (Expo). In-app persistence + Socket.IO
realtime + FCM push.

## 1. Purpose

Replace the mobile mock notification screen with a real notifications subsystem:
persist notifications per user, deliver them in real time over Socket.IO, and push
them to devices via FCM. Notifications are generated by backend events (order
status changes, driver acceptance, payment confirmation).

## 2. Current state

- Mobile has a **mock-only** screen (`NotificationsScreen.tsx` uses
  `mockNotifications` hardcoded). No API.
- Backend has **no** notification module.
- Socket.IO infra exists (`/tracking` + `/dispatch` namespaces, `SocketAuthAdapter`,
  `OrderEventsPublisher` in-process pub/sub).
- `firebase-admin@14.2.0` is already a dependency (used for OTP); FCM reuses the
  same `FIREBASE_PROJECT_ID` + `GOOGLE_APPLICATION_CREDENTIALS`.

## 3. Design

### 3.1 Data model

```prisma
enum NotificationType {
  ORDER
  PAYMENT
  PROMO
  SYSTEM
}

model Notification {
  id        String           @id @default(uuid()) @db.Uuid
  userId    String           @db.Uuid
  type      NotificationType
  title     String
  body      String
  data      Json?            // e.g. { "orderId": "…" }
  isRead    Boolean          @default(false)
  readAt    DateTime?        @db.Timestamptz(3)
  createdAt DateTime         @default(now()) @db.Timestamptz(3)
  user      User             @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@index([userId, isRead, createdAt(sort: Desc)])
  @@index([userId, createdAt(sort: Desc)])
}

model DeviceToken {
  id         String   @id @default(uuid()) @db.Uuid
  userId     String   @db.Uuid
  token      String   @unique
  platform   String   @db.VarChar(16)   // IOS | ANDROID | WEB
  lastUsedAt DateTime @default(now()) @db.Timestamptz(3)
  createdAt  DateTime @default(now()) @db.Timestamptz(3)
  user       User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@index([userId, lastUsedAt(sort: Desc)])
}
```

`User` gains back-relations `notifications Notification[]` and
`deviceTokens DeviceToken[]`.

### 3.2 Socket namespace

New `/notifications` namespace + `NotificationsGateway`, mirroring
`tracking.gateway.ts`:

- On connection, authenticate via `SocketAuthAdapter` and join room
  `user:<userId>` (all roles).
- Emit `notification:new` to `user:<userId>` when a notification is created.

Shared event constant added to `packages/shared/src/socket.ts`:

```typescript
export const NOTIFICATIONS_NAMESPACE = '/notifications';
export const NotificationSocketEvent = {
  created: 'notification:new',
  sessionError: 'session:error',
} as const;
```

### 3.3 `NotificationsService`

```typescript
create(input: {
  userId: string;
  type: NotificationType;
  title: string;
  body: string;
  data?: Record<string, unknown>;
}): Promise<Notification>
```

`create()`:
1. Persists the `Notification`.
2. Emits Socket.IO `notification:new` to `user:<userId>` (best-effort; a failed
   emit never fails the persist).
3. Reads the user's `DeviceToken`s and sends FCM push (see 3.5). FCM errors for a
   given token (e.g. `messaging/registration-token-not-registered`) delete that
   token row and continue.

Query methods: `list(userId, { page, pageSize })`, `unreadCount(userId)`,
`markRead(userId, id)`, `markAllRead(userId)`.

### 3.4 API

| Method | Path | Auth | Notes |
|---|---|---|---|
| GET | `/notifications` | any | paginated list (newest first) |
| GET | `/notifications/unread-count` | any | `{ count }` |
| POST | `/notifications/:id/read` | any | mark one read (idempotent) |
| POST | `/notifications/read-all` | any | mark all read |
| POST | `/notifications/register-token` | any | `{ token, platform }` upsert device token |
| DELETE | `/notifications/register-token` | any | remove current token |

### 3.5 FCM

`FirebaseMessagingService` wraps `firebase-admin.messaging()`. Reuses the existing
Firebase admin app (same project/credentials already configured for OTP). Push
payload: `{ notification: { title, body }, data: { type, ...data } }`.

### 3.6 Triggers — event wiring

`NotificationsService` (or a small `NotificationTriggers` injectable) subscribes to
`OrderEventsPublisher`:

| Event | Recipient | Type |
|---|---|---|
| `orderStatusChanged` (any transition) | customer + assigned driver | ORDER |
| `driver accepted` (status → ACCEPTED) | customer | ORDER |
| payment `PAID_MANUAL` confirmed | customer | PAYMENT |

For `PAID_MANUAL`, the payments service calls a notification hook directly (see
invoice spec — invoice link email is the primary channel; the notification is the
fallback).

### 3.7 Mobile

- Add a device-token registration call on app start (after login), using Expo
  push token where available; otherwise skip (in-app Socket.IO still works).
- Wire `NotificationsScreen` to the real `/notifications` API + subscribe to the
  `/notifications` socket for live updates + unread badge.
- Update `NotificationsScreen.test.tsx` to mock the API/socket instead of
  hardcoded data.

## 4. Error handling

- FCM send failure is isolated: log + prune dead token, never throw to the caller.
- `markRead` on a notification owned by another user returns `404` (non-disclosure).
- Register/remove token require a valid auth actor.

## 5. Testing

- Unit: `NotificationsService.create` persists + emits + calls FCM; FCM failure
  prunes token without throwing.
- Unit: gateway join/emit room routing.
- Contract: OpenAPI covers the notification endpoints + `register-token`.
- Mobile: `NotificationsScreen.test.tsx` asserts list renders from API and
  unread-count updates.

## 6. Environment

FCM requires the Firebase admin app, already configured via existing
`FIREBASE_PROJECT_ID` and `GOOGLE_APPLICATION_CREDENTIALS`. No new env vars for
the in-app/Socket.IO path.

New (optional) env: `FCM_ENABLED` (`true`/`false`, default `false`) to gate push
delivery when no Firebase credentials are present in a given environment.
